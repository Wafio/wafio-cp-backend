# Wafio v1.10.1 release notes

Status: released 2026-11-02 from `main` (tag `v1.10.1`, commit `e66c1a82`; bundles built from the identical tree at `843f8b2c`). Previous release: [v1.10.0](v1.10.0.md) (2026-10-31).

A bug-fix release for the WAF agent.

- A WAF agent in front of PHP-FPM (`fcgi:` upstream) no longer keeps PHP-FPM workers busy after
  the traffic that opened them is gone.
- There are no new migrations, no gRPC protocol change and no new eBPF objects.

## Upgrade

Only the WAF agent changes behaviour. The control plane and host agent are rebuilt for one version
number, with the same code as v1.10.0.

- The schema stays at migration 000114, and no proto message changed. Every version mix with
  v1.10.0 and v1.9.0 works.
- The host agent ships the v1.10.0 eBPF objects unchanged (same SHA-256).
- Upgrade WAF agents that serve `fcgi:` routes first. Agents with only HTTP upstreams can wait.

## Changes

### FastCGI connection pool (WAF agent)

The WAF agent talks to PHP-FPM with `FCGI_KEEP_CONN`. Every open connection keeps one PHP-FPM
worker busy. PHP-FPM counts that worker as active, so `pm.max_spare_servers` never reaps it.

The pool never shrank:

- A pooled connection idle past `idle_conn_ms` was closed and replaced at once by a fresh dial.
- Idle connections were reused round-robin, which kept every one of them fresh.
- Nothing closed idle connections while no request arrived.
- A bundle apply rebuilt every route with a new pool and left the old pools open.

So after any burst the pool kept its peak size, and with it as many PHP-FPM workers (about 40 MB
each). On a production host with 3.8 GB of RAM this held up to 47 workers under light traffic. A
memory-heavy request then exhausted the host's memory, and the kernel killed its database
(2026-11-02).

Now:

- The idle pool is LIFO, so under light traffic the connections a burst opened are not reused and
  age out.
- An idle connection past `idle_conn_ms` (default 10 s) is closed and its slot released.
- A timer closes idle connections even when no request arrives.
- A connection returned to a closed pool is closed.
- A bundle apply closes the pools of the routes it replaces. Requests still running on such a pool
  close their connection when they finish.

HTTP, HTTPS and unix-socket HTTP upstreams were not affected: fasthttp closes their idle
connections after `idle_conn_ms` on its own.

Bursts still open as many PHP-FPM workers as there are concurrent requests, up to the pool's
`max_conns` and PHP-FPM's `pm.max_children`. Size `pm.max_children` for the host's memory.

## Rollback to v1.10.0

The schema is unchanged, so a rollback is a binary swap: put the v1.10.0 `wafio-waf-agent` binary
back and reload the agent. The FastCGI pool then keeps PHP-FPM workers again.

## Verification

- New tests:
  - the pool shrinks back to one connection under light traffic after a burst, and to none
    without traffic;
  - LIFO reuse;
  - a stale idle connection releases its slot;
  - a connection returned to a closed pool is closed;
  - a bundle reload closes the replaced pool and keeps the live one. This test fails without the
    `applyBundle` change.
- Gates passed on `development` (`./scripts/ci-local.sh`): go build, go vet, golangci-lint,
  `go test ./...`, the strict corpus, the race detector (engine, application, agent), govulncheck,
  eBPF vet and the frontend checks. Spec/code drift is clean at the release head.
- Published bundles: the SHA-256 downloaded from `wafio.cloud` matches the manifest and the local
  build, and each Ed25519 signature verifies against the release key:
  - control plane `8eb9492d…`;
  - WAF agent `3d0277c1…`;
  - host agent `dbd57c9d…`.
- Affected host (Ubuntu 24.04, PHP-FPM 8.3, two `fcgi:` apps), upgraded from v1.9.0 with the
  published installer on 2026-11-02: control plane, WAF agent and host agent report v1.10.1, XDP
  and 40 of 40 tracepoints attached, an SQLi probe is blocked (403) on both apps, and the
  connections the WAF agent holds to PHP-FPM fall from 2 to 0 after 25 s without traffic
  (v1.9.0 held 6 to 8 at any time). Not deployed on the demo.
- Not run locally: gitleaks (not installed on the build Mac), and hosted CI, which has no GitHub
  Actions minutes left.
