# Wafio v1.10.0 release notes

Status: released 2026-10-31 from `main` (tag `v1.10.0`, commit `dee0fd90`). Previous release: [v1.9.0](v1.9.0.md) (2026-10-17).

A feature and security release.

- The host firewall loads again on Ubuntu 22.04 (kernel 5.15).
- The WAF engine moves to Coraza v3.8.1, which closes 12 reachable Coraza vulnerabilities.
- Field rules and custom rules can read fields deep inside JSON, form and multipart bodies.
- The installer can run the control plane's database in its own Docker container.
- IP reputation no longer blocks an application in monitor mode.
- There are no new migrations and no gRPC protocol change.

## Upgrade

The order is control plane, then host agents, then WAF agents. No version mix is refused:

- The schema stays at migration 000114, so the control plane upgrade runs no migration.
- No proto message changed. v1.9.0 agents run unchanged under a v1.10.0 control plane, and v1.10.0
  agents run under a v1.9.0 control plane.
- The new field rule and custom rule paths need v1.10.0 WAF agents. A v1.9.0 agent reports neither
  `field_rules_v2` nor `custom_rule_field_paths`, so the control plane adapts its bundle (see
  "Field and custom rules" below).
- Install the host agent together with its eBPF objects (the installer does). The new objects are
  the fix; an older object set keeps failing on 5.15.

## Changes

### Host firewall on Ubuntu 22.04

The v1.7.0 to v1.9.0 XDP object failed to load on Ubuntu 22.04's 5.15 kernel:

- `wafio_xdp_v6` passed the verifier's limit of 1M processed instructions, and `wafio_xdp_v4`
  reached 905k.
- The host firewall stayed off while runtime tracing ran.
- Debian 5.10/6.1 and Ubuntu 6.8 accepted the same object.

The checks after the list and geo stage now run in one global function for both address families,
and no maybe-NULL pointer is held across checks. The objects load on Ubuntu 5.15.0-191 at
312k/423k/312k/584k processed instructions (entry/v4/v6/TC egress), and at 220k/185k/187k/383k on
6.8.

### WAF engine: Coraza v3.8.1 and go1.26.10

- govulncheck reported 12 reachable Coraza v3.7.0 vulnerabilities (GO-2026-6668 to 6699, several
  of them WAF bypasses) and GO-2026-6809 in `crypto/x509` of go1.26.9. Both upgrades close them.
  `golang.org/x/net` v0.62.0 closes GO-2026-6860.
- Coraza v3.8.1 changes what it extracts, and the CRS body view follows it:
  - `SecArgumentsLimit` is set to 1024, so no value of the view is dropped.
  - Only the first Content-Type value selects the body processor.
  - Input Coraza still drops unseen counts as a gap (coverage `crs_budget`).
  - Valid JSON whose flattened form would outgrow Coraza's budget is re-encoded flat.
  - A quoted-printable multipart part can no longer hide later parts.
- Scanning allocates about 23% less, with identical verdicts on a 97,028-request replay. The CMD
  engine skips its argument-splitting regexes when their required markers are absent. Script rules
  run on the optimized Uddin sandbox.

### IP reputation and monitor mode

- The FireHOL gate used to answer a listed address with the 403 page, or a forced challenge, before
  analysis, whatever the route mode. An application in monitor mode therefore really blocked.
- Monitor mode now never blocks or challenges on reputation. When the policy blocks a level, the
  hit is recorded on the request's own decision as `monitor` (category `IPReputation`, detail
  `iprep_level1` or `iprep_level2`) and the request is forwarded.
- A level set to Challenge used to pass silently when no challenge acted on it (challenge off, or
  monitor mode). Such a hit is now logged (`iprep_levelN; challenge_off` or `monitor_mode`):
  - also on a WebSocket handshake;
  - also when a GUI rule's challenge falls back to allow.
- Block mode is otherwise unchanged.
- WebSocket handshake events are now emitted for `log` verdicts as well as `monitor`.
- Dashboard:
  - IP reputation has its own section in the WAF policy editor. It used to be hidden while the bot
    challenge was off.
  - The section warns when a level is set to Challenge while the challenge is off.
  - It notes that the lists cover public IPv4 only.
- Behaviour change to expect: monitor-mode applications stop blocking FireHOL level 1 addresses
  once their WAF agent runs v1.10.0.

### Field and custom rules

- **Field rules** (mask, encrypt_aes, decrypt_aes):
  - JSON: dot paths through arrays at any level, keys that hold dots, case-insensitive keys.
  - Form and multipart: every name spelling an application binds, including bracket names
    (`user[email]`).
  - New source `urlencoded`.
- **Custom rule conditions:**
  - New `param:<name>`: searches the query and every body type.
  - `json:` pointers with `*` segments and case-insensitive keys.
  - `query:`, `form:` and `multipart:` read names the way applications bind them.
- **Script rules** read the same fields with `waf_field`, `waf_values` and `waf_json`, from a 64 KiB
  JSON parse instead of the first 4 KB of the body.
- **Older WAF agents:** for a v1.9.0 agent, the control plane rewrites source `urlencoded` to `form`
  and disables rules that use `param:` or `*` segments (they would read empty values). Upgrade WAF
  agents before relying on deep paths.
- **Dashboard:** the rule path editor is split into Path, Inspection, Access, Limits, Login, Fields
  and encryption, and Advanced scores tabs.

### Installer

- `--db docker|host|existing` (or a menu) chooses where the control plane's PostgreSQL 17 and
  TimescaleDB run.
- `docker` runs a `wafio-db` container (`timescale/timescaledb:2.30.2-pg17`):
  - It is published on 127.0.0.1 only, and a PostgreSQL already on the host is never touched.
  - Its data lives in `/var/lib/wafio/postgresql`.
  - It is started before migrations on every upgrade.
- The settings grant for the free-disk alert uses the PostgreSQL client, not Debian's `pg_wrapper`.

### Other fixes

- MalwareBazaar hashes download from abuse.ch's v2 export URL; the old URL answers 410.
- Contract tests now check every HTTP response against `api/openapi.yaml`. Fixed along
  the way:
  - nil gRPC interface wiring;
  - password byte limits;
  - stored trace JSON handling;
  - trace policy responses;
  - firewall drop summary fields.

## Rollback to v1.9.0

The schema is unchanged, so a rollback is a binary swap. Before upgrading, keep a copy of
`/usr/local/bin/wafio*`, `/opt/wafio/frontend` and `/opt/wafio/ebpf` (or the v1.9.0 bundles).

- **Control plane.** Stop it, put the v1.9.0 `wafio` binary and frontend back, then start it.
  Field and custom rules saved with the new syntax stay stored. A v1.9.0 control plane sends them
  to agents unchanged.
- **WAF agent.** Put the v1.9.0 binary back. Monitor-mode applications block FireHOL level 1
  addresses again.
- **Host agent.** Put back the v1.9.0 binary and objects. The firewall fails to load again on
  Ubuntu 22.04's 5.15 kernel.
