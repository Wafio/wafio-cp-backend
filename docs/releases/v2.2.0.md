# Wafio v2.2.0 release notes

Released on 25 November 2026. This file lists what v2.2.0 changes for an operator, for the dashboard and for a client of the HTTP API.
It covers the control plane, the dashboard, the WAF agent, the host agent and the installers, which are released together. The
control plane, the dashboard and the host agent come from v2.1.0, the WAF agent from v2.1.1.

The installers (`deploy/install*.sh`), the bundle layout (`deploy/BUNDLE.md`) and the systemd units with their README
(`deploy/systemd/`) named below are in the wafio-release repository, not in this one. The READMEs of wafio-agent-waf and
wafio-agent-host hold the full lists of limits for the two agents.

## Upgrade

- Upgrade the control plane first, then the WAF agents and the host agents. The dashboard comes with the control plane. The control
  plane applies seven migrations, 000121 to 000127:
  - `000121_waf_agent_tls_key_reads`, `000122_expected_credential_readers` and `000125_waf_agent_tls_key_dir` add 16 built-in runtime
    security rules (see "Runtime security") and change the description and conditions of some existing built-in rules. They never
    write the flag a user can edit on a built-in rule, and custom rules stay as they are. Their down migrations remove the new
    rules and put the old text back.
  - `000123_app_fcgi_keep_conn` adds `apps.fcgi_keep_conn`, false for every app. Its down migration drops the column.
  - `000124_app_tls` adds the Gateway settings to `apps`, the tables `app_certificates`, `app_certificate_keys` and
    `app_tls_status`, and `agents.tls_certificates`. Every app starts with `tls_mode = 'proxy'`, so no app changes. Its down
    migration drops all of it: every uploaded certificate and key, every saved Gateway setting and every certificate status. The
    agent then serves an app that was in Gateway mode in plain HTTP on its Routing listen address.
  - `000126_waf_rollups` adds the tables `waf_rollup_state`, `waf_rollup_minute`, `waf_rollup_addr_seen` and `waf_rollup_hour`.
    Its down migration drops them; the control plane fills them again after the next up migration.
  - `000127_app_delivery` adds `apps.compression`, `apps.static_files`, `apps.cache` and `apps.tls_canonical_host`, the columns
    `agents.edge_redirects`, `edge_compression`, `edge_static_files` and `edge_cache`, and the tables `app_edge_status` and
    `app_cache_purges`. Its down migration drops all of them, so it loses every saved compression, files from a folder, cache and
    main host name setting, and the cache purge records.
  - `000123`, `000124` and `000127` wait at most 5 seconds for a table lock and fail after that. A failed run can be repeated: the
    statements skip what exists.
- From this release the control plane stores the id of `totp.enc_key` (the first 8 hex characters of its SHA-256, not the key) when
  it first starts, and refuses to start with a key of another id. Private keys of uploaded certificates are sealed with that key.
  To change the key, use the new command `wafio rekey` (see "Encryption key" below). No control plane starts while
  `wafio rekey --apply` runs.
- A v2.1.x WAF agent keeps working with a v2.2.0 control plane. Gateway, compression, the main host name and path prefix, files from
  a folder and the response cache need a v2.2.0 WAF agent. Without one the dashboard says on the tab that the agent is too old, and
  the API refuses a save that turns the part on: `409 TLS_UNSUPPORTED` for Gateway, `409 AGENT_TOO_OLD` for the others. Moving an
  application that uses such a part to an older agent is refused with `409 FEATURE_UNSUPPORTED`. An agent that has not reported its
  features yet is let through.
- Gateway is off for every application. An upgraded host keeps serving behind its existing web server (nginx or another) with no
  change. Compression, files from a folder and the cache are off too, and no application has a main host name or a path prefix, so
  a v2.2.0 WAF agent behaves as before until an application turns a part on.
- The WAF agent unit has a cache directory now: `CacheDirectory=wafio-waf` with mode 0700, so systemd makes `/var/cache/wafio-waf`
  for the user `wafio` at each start. It holds copies of answers only: stop the agent and delete the folder to empty the cache. The
  state directory `/var/lib/wafio-waf-agent` (`StateDirectory=`, as before) now also holds `tls/`, which the agent creates with mode
  0700 for certificate keys, the Let's Encrypt account key and the certificate state. The unit always comes from the bundle, so
  install the agent from the bundle and do not replace the binary alone: an agent without a usable cache directory leaves the cache
  off and the dashboard says so. The systemd README in wafio-release has the check for older systemd versions.
- A folder that an application serves as static files must be readable by `wafio` and must not lie under `/home`, `/root` or
  `/run/user`, which the unit hides with `ProtectHome=yes`. The installers write no drop-in for this.
- Install the control plane with its installer from the bundle. It takes back `/opt/wafio` and `/etc/wafio`, which the installers
  of v2.0.0 and v2.1.0 gave to the service user (see "Security"). A host agent does not protect a WAF agent whose binary or
  directory a non-root account owns.
- Upgrade the host agents with the control plane. The trace forwarding filter has a new revision (6, it was 3), and a host agent
  applies a filter only of its own revision. A v2.1.0 host agent keeps working and sends every runtime security event, with no
  filtering, until it is upgraded.
- FastCGI upstreams close the connection after each reply, as in v2.1.1. Keeping connections open is a per-application switch now,
  and it is off.

## New

### Gateway: HTTPS from the WAF agent

- An application can be served over HTTPS by the WAF agent itself, with no web server in front. The settings are on the Gateway tab
  of the application page (between Maintenance and Speed) behind a switch that is off by default. With the switch off the tab says
  that requests reach the agent on the Routing listen address and that a web server or CDN in front handles HTTPS. Turning the
  switch off puts every saved value back.
- Settings: 1 to 100 host names (plain DNS names, no wildcard, IP address or port; a name belongs to one application on a
  listener), the HTTPS address (default `0.0.0.0:443`), an optional HTTP address that redirects to HTTPS ("Redirect HTTP to
  HTTPS"), the certificate source and the main host name (see below). Switching to Gateway opens a dialog that lists the checks
  (source, host names, agent, certificate, host credential, trusted proxies) and what visitors get meanwhile.
- The listener speaks TLS 1.2 and 1.3 and offers HTTP/1.1 only. The SNI name picks the application and its certificate. A request
  whose `Host` differs from the SNI name gets `421` and the connection closes. A client that sends no name, or a name no
  application has, gets no handshake. Applications can share one HTTPS address. An application in Gateway opens no plain listener of
  its own, and the application behind it is told `X-Forwarded-Proto: https`.
- The HTTP address answers every method with `308` to the same path and query on HTTPS, for the host names of the application, and
  `404` for any other host.
- If another program holds the address (a web server on port 443, say), the agent cannot bind it, tries again every minute and
  reports `cannot listen on <address>: address in use`. Move the web server off the port before you turn Gateway on.
- Uploaded certificates: upload the chain and the unencrypted private key in PEM on the Gateway tab (up to 10 certificates in the
  chain; the key is RSA of 2048 to 4096 bits, ECDSA P-256 or ECDSA P-384). The control plane checks that the key belongs to the
  leaf, that the certificate has not expired and that it covers every host name. A chain that does not lead to a root that
  browsers trust is accepted with a warning, which fits a private CA. The control plane keeps the key sealed with AES-GCM under
  `totp.enc_key`, in a table of its own, and sends it only to the agent that serves the application. That agent needs a credential
  bound to its host (enrolled with a host key), or the API answers `409 AGENT_NOT_HOST_BOUND`. The agent keeps the files in
  `/var/lib/wafio-waf-agent/tls/` with mode 0600, serves a new certificate from the next handshake and keeps open connections.
- The host keeps a copy of the key of an uploaded certificate. When you delete an agent or revoke or delete a host that served one,
  upload a new certificate with a new key. The dashboard confirm says so.
- Let's Encrypt: the agent orders one certificate for all host names of the application. The dashboard asks you to confirm the
  Let's Encrypt terms. The directory is Let's Encrypt's by default; `--acme-directory` or `WAFIO_ACME_DIRECTORY` in
  `/etc/wafio/waf-agent.env` names another one (https only).
  - The agent proves the names with TLS-ALPN-01 on the HTTPS listener (port 443) and HTTP-01 on the HTTP address (port 80) and on
    the HTTPS listener. After a failed order it tries the other challenge. Ports 80 and 443 must be open to everyone, because the
    authority checks from several networks: a host firewall or an XDP allowlist that lets only some addresses through makes the
    order fail. HTTP-01 on port 80 needs the HTTP address, so turn on "Redirect HTTP to HTTPS".
  - Until the first certificate arrives the agent serves a self-signed placeholder: visitors get a browser warning and a `503`
    page, and the HTTP address answers `503` with `Retry-After: 60` instead of the `308`.
  - A renewal starts when a third of the lifetime is left (30 days before the end of a 90-day certificate), when a host name is
    not covered, or when you press the request button (disabled for five minutes after the last request, or for as long as a
    refusal asked). A failed order is tried again after 10 minutes, then 1 hour, 4 hours, 12 hours and a day. A rate limit makes the
    app wait for the time the authority names, up to 7 days. A failing renewal keeps serving the current certificate. A restart or
    a reload does not order again at once: the agent keeps the state of its orders in `state.json` in the key directory.
  - Behind Cloudflare, SSL/TLS mode "Full" works with HTTP-01. It does not work with TLS-ALPN-01, which Cloudflare does not pass,
    so the first request usually fails and the retry over HTTP-01 succeeds. The mode that connects over plain HTTP loops.
- Certificate card: it shows the source, the names, the issuer, the dates and the key type, and for an ordered certificate the
  state the agent reports (pending, active or failed, with the reason and the time of the next try). Expiry shows as an alert on
  the card and as a badge in the header of the application page while the application is in Gateway.
- Expiry mail: while the control plane has a mail server configured, the owners and members of the project (not viewers) get one
  mail for each level of each certificate, with a link to the Gateway tab. The levels are 30, 14, 3 and 1 days left for an uploaded
  certificate, and 14, 3 and 1 for Let's Encrypt, where a mail means the renewal is late (a certificate with a short lifetime has
  the 1 day level only). The control plane checks every 6 hours.
- API: `GET` and `PUT /api/projects/{id}/apps/{appId}/tls`, `POST .../tls/acme` (order now), `POST` and `DELETE
  .../tls/certificate`. The audit log records `app.tls_updated` and `agent.certificate_delivered`; neither holds key material.

### Main host name and path prefix

- Main host name (Gateway tab, Addresses): a visitor who comes in under another host name of the application gets `308` to
  `https://<main host>` with the same path and query, and the HTTP address sends every visitor there in one hop. `308` keeps the
  method. The host in `Location` comes from the saved setting, never from the request. A blocked request is never redirected, and
  neither is a request that asks for an upgrade. Browsers keep a `308`, so a main host that you change later may keep sending
  returning visitors to the old name for a while. It works in Gateway mode only. API: `canonical_host` in the TLS settings.
- Path prefix (Routing tab, Advanced): for an application that lives under a path such as `/shop`. `/shop/cart` reaches the
  application as `/cart`. Any other path, `/shopping` and `/admin` included, gets `404` from the agent and never reaches the
  application, and a WebSocket handshake follows the same rule. The prefix is matched after the agent decodes the path and
  resolves `.` and `..`. Rules, decision events and the cache key keep the public path. Links and `Location` headers that the
  application writes are not rewritten and must include the prefix. API: `proxy_config.strip_path_prefix`.

### Speed: compression, files from a folder and the response cache

- The Speed tab of the application page has three parts, each with its own switch and Save, a line that says whether the agent
  runs it (waiting, in use, refused with the reason, too old, offline) and counters in words. Every setting is checked on every
  save (`400 INVALID_DELIVERY_SETTINGS` names the field). A save pushes a new bundle and writes an audit entry
  (`app.compression_updated`, `app.static_files_updated`, `app.cache_updated`). The agent applies the settings itself and may
  refuse them; a refusal keeps the settings it already runs. A save is refused with `409 BUNDLE_TOO_LARGE` when the bundle of the
  agent would pass 4,193,280 bytes.
- Compression: gzip or brotli, whichever the visitor's `Accept-Encoding` prefers (a tie goes to brotli). Gzip answers are encoded
  in Rust (`miniz_oxide`). It applies to text, JSON, JavaScript, XML, WebAssembly, SVG and some fonts, when the answer is at least
  `min_bytes` (default 1 KiB) and at most 8 MiB. Streamed answers, `HEAD`, `206`, `304` and answers that carry a
  `Content-Encoding` or `Cache-Control: no-transform` are left alone. A compressed answer gets a weak `ETag` and `Vary:
  Accept-Encoding`. For a signed-in request HTML and JSON are not compressed (the BREACH attack); a request is signed in as
  described under the cache below.
- Files from a folder: the agent answers `GET` and `HEAD` for the files of one folder after the WAF verdict, without asking the
  application. A request whose file is not in the folder goes to the application, or gets `404` when you choose "the folder is the
  whole site". It sends the type, `ETag`, `Last-Modified`, `Accept-Ranges`, range and conditional requests, and a browser cache time
  you set. It never serves folder listings, names that start with a dot (except `.well-known`), PHP files, symbolic links or a
  path with a part named like a system file or folder, such as `profile`, `network` or `shadow`. A folder is refused when it is `/`
  or lies in, or above, `/etc`, `/root`, `/proc`, `/sys`, `/dev`, `/run`, `/boot`, `/usr`, `/var/lib/wafio-waf-agent` or
  `/var/cache/wafio-waf`. The agent checks the folder when it applies the bundle and again on every request, so a `current` link
  that moves somewhere forbidden serves nothing. A refusal carries a code (`root_missing`, `root_not_directory`,
  `root_unreadable`, `root_forbidden` or `invalid`) and the application keeps the folder it had.
- Response cache: the agent keeps answers of the application and sends them again without asking it. It is off by default. With it
  on, the defaults are: images, fonts, media, styles and scripts that carry no lifetime are kept for 1 hour; stored copies are sent
  for 10 minutes while the application is down; 1 GiB of disk, 32 MiB of memory and objects of up to 8 MiB.
  - Copies live in `/var/cache/wafio-waf`. Copies up to 256 KiB also go to memory from their second hit. Both tiers evict the least
    used copies first. The agent refuses settings whose disk total passes the free space minus 5 percent of the file system
    (`disk_too_small`) or whose memory total passes a quarter of the host memory (`memory_too_small`). With under 5 percent of the
    file system free it stores nothing and removes the least used copies.
  - Only a `GET` or `HEAD` that the WAF verdict allows is looked up. A `GET` without `Range` stores the answer when it has a status
    of 200, 203, 300, 301, 308, 404 or 410 and a lifetime (`s-maxage`, `max-age`, `Expires`, a path rule, or the default for a
    file type). Never stored: answers with `Set-Cookie`, `private`, `no-store` or `no-cache`, a `Vary` of `*`, `Cookie` or
    `Authorization`, or an object over the limit. Every answer of a looked-up path carries `X-Cache`: `HIT`, `STALE`, `MISS` or
    `BYPASS`.
  - A signed-in visitor skips the cache. A request is signed in when it has an `Authorization` header, user information in the
    address, or a session cookie: a cookie whose name holds `sess`, starts with `wordpress_logged_in_`, `wp-postpass_`,
    `remember_web_`, `remember-me` or `.AspNetCore.`, or is `JSESSIONID` or `connect.sid`, or one of up to 20 names you list. An
    application with another session cookie name must list it. Only a path rule with "Also for signed-in visitors" reads and fills
    copies for them, and it shares them between all visitors of that path, so use it for a path that shows one page to everyone.
  - A request with another cookie (an analytics cookie, say) is still answered from a stored copy. The answer to it is stored only
    when it says `public` or has `s-maxage`, or is a file type while the default lifetime is on.
  - Up to 50 path rules; the longest matching prefix decides. A rule keeps answers for a time you set, or bypasses the cache for
    that path. A path that contains `;` is never cached.
  - A copy past its life is sent as `STALE` within `stale-while-revalidate` and while the application is down (`stale-if-error`,
    else the 10 minute setting), or confirmed with the application through `ETag` or `Last-Modified`. A `POST`, `PUT`, `PATCH` or
    `DELETE` with a 2xx or 3xx answer ends the copies of the same URL. 100 requests for a page that has no copy make one request
    to the application: the others wait up to 5 seconds for it.
  - With the cache on, a peer's `X-Forwarded-*` other than `-For`, `-Host` and `-Proto`, and `X-Original-*`, `X-Host`,
    `X-Rewrite-URL`, `Forwarded`, `Front-End-Https` and `X-Url-Scheme`, are not sent to the application, unless the peer is a proxy
    that the route trusts.
  - Remove stored copies: under the cache settings, for one address, for every path that starts with a prefix, or for the whole
    application. API: `POST /api/projects/{id}/apps/{appId}/cache/purge`, with scope `url`, `prefix` or `app`; it answers `202`,
    or `409 CACHE_OFF` while the cache of the application is off. An agent that is offline gets the request when it connects
    again.
- API: `GET /api/projects/{id}/apps/{appId}/delivery` returns the three settings and what the agent last reported about them. `PUT`
  `.../delivery/compression`, `.../delivery/static-files` and `.../delivery/cache` replace one part each.

### FastCGI keep-alive for each application

- The Routing tab has the switch "Keep FastCGI connections open between requests" (API: `fcgi_keep_conn` on applications and
  routes). It is off. Off, the agent opens one connection to PHP-FPM for each request and closes it after the reply, as v2.1.1
  does. On, it keeps idle connections for `idle_conn_ms`.
- Turn it on only when PHP is at least 8.2.36, 8.3.37, 8.4.28 or 8.5.13 for its 8.2, 8.3, 8.4 or 8.5 series. 8.1 and older are not
  fixed: PHP-FPM before these releases can run unread request body bytes as a second request (CVE-2026-129289). With the switch
  on, the agent gives each request a random id, fails a request whose reply carries another id, and closes a connection with
  input waiting. These checks narrow the risk and do not replace the PHP update.
- A v2.1.1 agent ignores the switch and always closes the connection. An agent before 2.1.1 ignores it and keeps connections open.

### Trusted proxies: Cloudflare preset

- The Routing tab, Advanced, has a button "Use Cloudflare's addresses" under Trusted proxies. It fills the list with Cloudflare's
  published ranges plus `127.0.0.1` and `::1`, and turns forwarded headers on. It asks first when the list holds other entries, or
  when it is empty with forwarded headers on, because the empty list trusts loopback and the private ranges and the button would
  drop them.
- The ranges are a copy of https://www.cloudflare.com/ips/ taken on 24 November 2026. The dashboard does not refresh them.
- Every Cloudflare customer's traffic comes from these addresses, so another Cloudflare account may be able to set the client
  address. If a web server or load balancer sits between Cloudflare and the agent, add its address to the list, or every visitor
  looks like that server. The agent asks no client certificate, so Authenticated Origin Pulls limits nobody; to accept only your
  own zone use a Cloudflare Tunnel and trust the address `cloudflared` connects from.

### Dashboard widgets read from rollups

- The app Monitoring tab and the project Overview read counters, timelines, distinct client addresses, top lists and the map from
  tables that the control plane fills from the decisions (migration 000126), so a window of 30 days no longer reads every decision
  in it. The job runs inside `wafio serve` once a minute and needs no flag or key. Of several control planes on one database, one
  works.
- After the upgrade the job fills the tables from the newest hour back, up to 20 seconds a minute, as far as the decisions go. A
  range that is not filled yet is read from the decisions (exact, and slower), so long windows get faster over the first hours. A
  control plane that was down catches up an hour a pass.
- Counters, timelines of whole minutes and the distinct client addresses of a window that ends now are exact. Top lists, the map
  and the distinct hosts are approximate: an hour keeps only its busiest values (500 URIs, 500 user agents, 1,000 client
  addresses, 200 categories, 200 hosts and 50 methods), so a value is counted only in the hours where it was among them. Its
  count can be well below the real one, and it can be missing from the list.
- The tables are trimmed with the retention of the decisions, and saving the retention of the telemetry tables starts a pass that
  trims them too; in the first hour after an upgrade a shortening takes effect when that hour ends. On a test set of 33 million
  decisions over 30 days the tables took about 2.4 GB with their indexes.

### Runtime security

- 16 new built-in rules lower the incidents that the platform's own services and package runs opened. Each stores the event and
  tags it; only the incident goes. The rules for the WAF agent, nginx and systemd-networkd need a v2.2.0 host agent, which marks
  those processes as verified.
  - The WAF agent reading, writing, renaming, removing and changing the mode of its own TLS keys under
    `/var/lib/wafio-waf-agent/tls`, `/etc/ssl/private` and `/etc/letsencrypt/live`, as an unprivileged user.
  - The nginx master reading its TLS key, also under certbot after a renewal.
  - systemd-networkd opening its ICMPv6 raw socket and its LLDP packet socket.
  - `debconf`, `dpkg-preconfigure`, `dracut` and `pg_ctlcluster` reading `/etc/shadow` in package runs and at boot, `needrestart`
    and its hook reading `/proc/<pid>/environ`, and `dpkg-deb` and `dracut` setting root ownership.
- A directory listing of a key directory, a read of `/etc/login.defs` and the README that certbot writes into
  `/etc/letsencrypt/live` no longer count as credential access.
- Built-in rules that trust a verified daemon's name (systemd, dockerd, containerd, sshd) now also need real UID 0, because a thread
  of any verified process can rename itself.
- A detection rule condition can test `args`, the destination of a rename. A rule with a condition on `args` must also have the
  condition `event_name` equals `rename`; the API refuses it otherwise.

### Host agent

- The WAF agent, `nginx` (the master process), `systemd-networkd` and `systemd-executor` join the protected processes. A Kill
  policy never terminates them, and their trace events carry `exe_verified`, so the control plane can tell the WAF agent reading its
  key from another process reading it.
- The mark is stricter. The agent trusts a file only when root alone can write it and every directory above it, tells files apart
  by device and inode, and checks the unit: the WAF agent counts only inside `wafio-waf-agent.service` and systemd-networkd only
  inside its own unit. A WAF agent whose binary or directory a non-root account owns is not protected, and the log says that the path can
  be written by an account other than root. The self-check line shows it (`untrusted_owner=`):
  `journalctl -u wafio-host-agent -b | grep 'protected-process self-check'`.
- `WAFIO_PROTECTED_PROCESSES` and `WAFIO_PROTECTED_EXE_PATHS` follow a symbolic link in a configured path only out of directories
  that only root can write, and the agent warns about a path that links to a shell or an interpreter. A host with only cgroup v1
  loses the mark of the WAF agent and systemd-networkd at `exec` and gets it back at the next refresh, 5 seconds later.

### Encryption key

- `wafio rekey` moves every value sealed with `totp.enc_key` to a new key: TOTP secrets, the SMTP password, the MalwareBazaar key
  and the private keys of uploaded certificates. Without `--apply` it reports counts and changes nothing. With `--apply` it rewrites
  the values in one transaction and records `admin.encryption_key_rotated` in the system audit log. The old key goes in
  `WAFIO_OLD_TOTP_ENC_KEY` on the command line of that one command. The steps are in `docs/operations/rotate-encryption-key.md`.

## Changed

- Scheme told to the application, with the cache on or off. A TLS connection that the agent ended says `https`. A proxy that the
  route trusts (`trust_forwarded` and `trusted_proxies`) has its first `X-Forwarded-Proto` line passed on as it wrote it. From any
  other peer the value is `https` when its first value is `https`, else `http` (nothing for a FastCGI application). Any other
  spelling of the line is dropped, and the agent never sends a second line next to its own. With the cache on the value is part of
  the cache key.
- The dashboard places decisions by the time the control plane recorded them, not by the event time the agent reports, in the app
  timeline, the maps and the count by method. The window of `GET /apps/{appId}/waf/summary` is capped at 43,200 minutes (30
  days); it had no upper bound. The previous window of an Overview summary reports 0 distinct addresses.
- The WAF agent acks a bundle before it writes its bundle cache, which a thread of its own does, so a slow disk no longer holds up
  the commands that follow. A bundle that cannot bind an address is tried again every minute, with no limit.
- The WAF agent marks itself not dumpable at start: a crash leaves no core dump with keys in it, and a process of its own user
  cannot attach to it with `ptrace`.
- `idle_conn_ms` applies to FastCGI routes again, but only while `fcgi_keep_conn` is on for the application.
- The agent protocol gains the messages `CertificateInstall`, `CertificateStatus`, `EdgeStatus` and `CachePurge` and the Hello
  features `tls_certificates`, `edge_redirects`, `edge_compression`, `edge_static_files` and `edge_cache` (shared module up to
  `shared/v0.4.0`). A reader skips messages and feature names it does not know.
- The agent's metrics listener (`WAFIO_METRICS_ADDR`, loopback only) has new series: `wafio_waf_acme_orders_total`,
  `wafio_waf_certificate_installs_total`, `wafio_waf_tls_certificate_expiry_seconds`, and the families `wafio_waf_compression_*`,
  `wafio_waf_static_*` and `wafio_waf_cache_*`.
- Each bundle README ends with a paragraph on the licences of the bundle.
- Go modules and the dashboard's packages are updated; among them gRPC moves from a development build to v1.85.0.

## Fixed

- `response_decrypt_aes` and `response_field_rules` of a path now run on answers from FastCGI upstreams. Before, they ran on
  answers from HTTP upstreams only.
- The SBOM of the WAF agent bundle listed no package. It now lists the Rust crates the build linked, and `scripts/release.sh`
  refuses a bundle whose SBOM is missing, names another version or lists none.
- The maintenance page preview no longer stays blank, and the custom HTML field opens with the standard page to edit.
- The code editors of the dashboard show syntax colours.

## Security

- The control plane installers of v2.0.0 and v2.1.0 ran `chown -R` over `/opt/wafio`, `/etc/wafio`, `/var/log/wafio` and
  `/var/lib/wafio`. The control plane unit runs as the service user with no sandbox, and `/opt/wafio` and `/etc/wafio` also hold the
  binaries, eBPF objects and settings of the host agent, which runs as root. Code running as the control plane could replace one of
  them and get root at the next start of the host agent. The WAF agent runs as the same user and could do the same. The installer
  of v2.2.0 gives root those two trees without group or other write bits, makes `config.yaml` `root:wafio` with mode 0640, and
  gives the service user only `/opt/wafio/security-data` and `/etc/wafio/security-data`. `/var/log/wafio` and `/var/lib/wafio` are
  no longer handed over. Running the installer again takes back what the old one gave away. On a host where the `wafio` account may
  have been abused, install the agent bundles again as well.
- The private key of an uploaded certificate is sealed with AES-GCM bound to its project and certificate, kept in a table that no
  certificate query reads, and sent only to the agent that serves the application. The agent zeroes the buffers it made for the
  key where it can; the gRPC and TLS libraries keep copies of their own. The key is in no log line, status message, bundle cache or
  heartbeat.
- The host agent protects the WAF agent, `nginx` and systemd-networkd by file identity and unit, as described under "Host agent".

## Known issues

- With the response cache on, a request whose answer is stored costs about 2.4 to 3 times the agent CPU of plain forwarding. This is
  the worst case, where every request is for a new URL. It applies only to an application that turns the cache on.
- With the cache on, pages that set a cookie pass about 2 percent slower than with the cache off. This applies only to an
  application that turns the cache on.
- A `GET` whose answer was fetched before a `POST` to the same URL can still be stored after the `POST` ended the copies of that
  URL. Remove the address under Speed, Remove stored copies, if that matters.

## Not in this release

- The HTTPS listener of the WAF agent offers HTTP/1.1 only, and the agent asks no client certificate.
- Let's Encrypt orders use TLS-ALPN-01 and HTTP-01. There is no DNS-01 and no wildcard host name.
- The error text for `match_dest_ip` in the shared module still names the kernel connect blocklist. It changes with the next shared
  tag.
