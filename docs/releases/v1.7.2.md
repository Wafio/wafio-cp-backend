# Wafio v1.7.2 release notes

Status: released 2026-10-11 from `main` (tag `v1.7.2`). Previous release: [v1.7.1](v1.7.1.md) (2026-10-11).

A patch release on top of v1.7.1. No database migration, no agent protocol change and no eBPF change.
Upgrade the WAF agents: the fix is in the detection engine they run.

## Fixed

- **Bot protection blocked every WebSocket from Chrome.** The client-hints check flags a Chromium user
  agent that sends neither `Sec-CH-UA` nor `Sec-Fetch-Mode` as a spoofed browser (`missing_sec_ch_ua`,
  base score, a block in block mode). Chrome sends neither header on a WebSocket opening handshake, so
  applications using WebSockets (socket.io and others) were cut off or fell back to polling. A
  well-formed RFC 6455 opening handshake (GET, `Upgrade: websocket`, `Connection: upgrade`,
  `Sec-WebSocket-Version: 13`, a `Sec-WebSocket-Key` of 16 bytes) is no longer flagged by this one
  check; headless Chrome, the user-agent blocklist and the platform-mismatch checks still apply. This
  adds no bypass: the check could already be passed by sending any `Sec-CH-UA` value.

## Operator note

A reverse proxy in front of the WAF agent must pass the upgrade through, or WebSockets never reach it.
For nginx: `proxy_http_version 1.1;`, `proxy_set_header Upgrade $http_upgrade;` and
`proxy_set_header Connection` set to `upgrade` when `$http_upgrade` is not empty (a `map`), plus a
`proxy_read_timeout` longer than the application's idle period.
