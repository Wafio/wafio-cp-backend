# Wafio v2.1.0 release notes

Released on 18 November 2026. This file lists what v2.1.0 changes for an operator, for the dashboard and for a client of the HTTP API.
It covers the control plane, the dashboard, the WAF agent, the host agent and the installers, which are released together.

The installers (`deploy/install*.sh`), the bundle layout (`deploy/BUNDLE.md`), `scripts/release.sh` and `scripts/publish-release.sh`
named below are in the wafio-release repository, not in this one.

## Upgrade

- Upgrade the control plane first, then the agents. The control plane applies two migrations, 000119 and 000120.
  `000119_app_maintenance` adds the nullable column `apps.maintenance`. `000120_trace_policy_block_removed` turns every runtime
  policy whose action is `block` into `alert` (see "Removed" below); it changes no other row. The down migration of 000120 does
  nothing, because the old action cannot be told apart afterwards.
- A v2.0.0 agent keeps working with a v2.1.0 control plane, and a v2.1.0 agent with a v2.0.0 control plane. Maintenance mode needs a
  v2.1.0 WAF agent: the control plane refuses to turn it on for an application whose agent does not report the feature
  (`409 MAINTENANCE_UNSUPPORTED`).
- The host agent bundle holds three eBPF objects: `wafio_xdp.o`, `wafio_tc.o` and `wafio_trace.o`. `wafio_lsm.o` is gone. The
  installers remove a `wafio_lsm.o` that an earlier version left in the eBPF directory.
- The host agent flags `--lsm` and `--lsm-block-connect` are still accepted and do nothing, so a unit file that passes one keeps
  starting. Remove them when you next edit the unit.
- A host agent that stays connected while the control plane is upgraded keeps a `block` policy it already holds until the next
  policy change on that host or a restart of the agent. This has no effect on enforcement: see "Removed".
- A WAF agent bundle without its systemd unit is refused. The unit always comes from the bundle; the installers no longer write one
  of their own for the WAF agent.

## New

### Maintenance mode for an application

- An application can be put in maintenance mode from its page in the dashboard (tab Maintenance) or with
  `GET` and `PUT /api/projects/{id}/apps/{appId}/maintenance`.
- Visitors get `503` with `Retry-After` (when an expected end is set) and `Cache-Control: no-store`. The body is HTML, JSON or XML,
  chosen from the `Accept` header. The stock page can be replaced by a custom HTML page; the placeholders `{{WAFIO_MESSAGE}}` and
  `{{WAFIO_END_TIME}}` may each be used at most 16 times.
- Listed IP addresses and listed paths pass through to the application. `/` cannot be listed as an allowed path.
- The agent decides from the request head, so a large upload is answered with `503` and not read. Open WebSocket and server-sent
  event connections of the application are closed (WebSocket close code 1001) when maintenance starts. CORS preflights are
  answered so that a browser can read the `503`.
- A maintenance page travels in the agent bundle. The control plane keeps the bundle of one agent under 4,193,280 bytes and
  refuses a change that would pass it (`409 MAINTENANCE_BUNDLE_TOO_LARGE`).
- Limits that remain are listed in the README of wafio-agent-waf: a credentialed preflight, an upload past the drain bound, a
  server-sent event stream across a reload, and streams that are not server-sent events.

### BPF map sizes follow the memory of the host

- The host agent used to preallocate about 190 MB of kernel memory for its BPF maps on every host. It now sizes them from the
  memory of the host (and from a cgroup v2 memory limit, when one is set): about 28 MB at 1 GB, 45 MB at 2 GB, 90 MB at 4 GB and
  the full sizes from 8 GB.
- `--ebpf-map-scale`, or `WAFIO_EBPF_MAP_SCALE` in `/etc/wafio/host-agent.env`, takes `auto` (the default) or a number above 0 and
  at most 1. `1` gives the full sizes on any host.
- A full map does not drop legitimate traffic. A host-opened TCP flow that lost its connection tracking entry passes again when
  the kernel still holds the socket. The jail is a hash map now and never evicts a jailed address; a full jail answers
  `409 IP_LIST_FULL`. The README of wafio-agent-host has the table of what each map does when it is full.
- The status of the host agent carries `map_sizing` (scale, where it came from, and for each map its size, its entries and how
  often it was full). The dashboard shows it under Firewall, Overview and under Runtime security, Agent.

## Removed

### BPF-LSM and the runtime policy action `block`

- The action `block` of a runtime policy relied on a BPF-LSM connect blocklist in the host agent. That path needed the flag
  `--lsm-block-connect`, which was off by default and not documented, and a kernel with `bpf` in its LSM list. No installer turned
  it on, so a `block` policy recorded the event and denied nothing.
- The host agent no longer loads BPF-LSM programs. The remaining actions are `simulate`, `monitor`, `alert` and `kill`.
- To block outbound traffic to an address, add it to the firewall egress blocklist (Firewall, Access rules, Egress blocklist). It
  works on every supported kernel. To stop a process, use `kill`.
- API: creating, updating or copying a runtime policy with action `block` is refused with `400 BAD_REQUEST`. Stored `block`
  policies become `alert` (migration 000120); `enabled` is kept. Recorded events and enforcement log rows with action `block`
  stay readable.
- The trace status of the host agent no longer has `lsm_active`, `lsm_state` and `lsm_reports_suppressed`. `host_info.bpf_lsm` is
  still reported and stored, and not used.
- The count of enforcing policies in the host list counts `kill` policies only.

### Leftovers of version 1

- `GET /api/internal/waf/bundle` and `POST /api/internal/waf/ingest` are removed. No v2 agent calls them: the WAF agent takes its
  bundle and sends its decisions over the gRPC stream.
- The host agent no longer sends the `X-Agent-Key` header. The control plane accepts `X-Wafio-Host-Key` only, as in v2.0.0.
  `--agent-api-key` stays accepted and unused; a host agent whose only credential is that key starts, logs a warning and cannot
  push.
- Six host agent flags of the removed WAF pipeline and IP jail are gone. No installer or unit of any release passes them.
- The dashboard no longer redirects the bookmark paths of version 1.

## Changed

- The requests the WAF agent makes itself (the jail endpoint, the WebSocket handshake, the good bot lists, the captcha check and
  SIEM delivery) send the User-Agent `wafio-waf-agent/<version>`.
- Rule and upstream errors of the WAF agent use plain texts of their own.
- The Explore search of Runtime security matches an address, and its label says so.

## Security

- `golang.org/x/crypto` is 0.59.0, which fixes GO-2026-5932.

## Not in this release

- The error text for `match_dest_ip` in the shared module still names the kernel connect blocklist. It changes with the next
  shared tag.
