# Wafio v1.7.0 release notes

Status: released 2026-10-10 from `main` (tag `v1.7.0`; first drafted 2026-09-30).
CI on `f8b7458d`: ebpf-vm (kernels 5.10, 5.15, 6.1, 6.12), hygiene and security green. The test server
(kernel 6.8) runs the agents and eBPF objects of `f8b7458d` since 2026-10-10 22:24 WIB: every program
loaded without a verifier error, no restarts, `firewall_features` `geo_allow` + `allowlist_ports`
reported; firewall in monitor mode, geo allow not yet tried on that host.
Previous public release: v1.6.15 (2026-09-25, built from about `e9f523e1`).

This release carries the third audit round and three findings from release verification, listed under
"Fixed in this release". It is one combined release: the work merged on 2026-10-10 (semantic
false-positive follow-up, CRS latency follow-up, geo allow mode, firewall IP lists v2, port-scoped
allowlist, Go toolchain update) is included.

## Highlights

- Script rules run in a sandbox (allowlist of pure functions and `waf_*` builtins, size, depth,
  operation, memory and regex budgets, in-flight cap); saving or editing needs the `owner` role.
- Client IP is the TCP peer unless it is a trusted proxy; geoblocking reads `RemoteAddr` only.
- The semantic stage reports coverage; a request with incomplete coverage runs CRS instead of
  passing as clean, and CRS reads a bounded view of large bodies.
- Host agent and WAF agent local APIs require a per-boot token.
- eBPF firewall: lockout guard, reply handling, fragment handling and a port-policy swap that
  never removes a rule that stays.
- Host firewall: geo allow mode ("allow only these countries, block the rest") with a lockout guard
  and a capability check, so older agents are never switched.
- Host firewall: IP lists v2 (prefix tries instead of expanded CIDRs, diff-based apply, a separate
  jail map, `IP_LIST_FULL` instead of eviction) and port-scoped allowlist entries (source, port,
  protocol). Writes in multi-host projects now need `agent_id` or `host_id`.
- Fewer semantic false positives (blazehttp semantic-only 409 to 299) and lower worst-case CRS
  latency (max 2.4 to 6.5 s down to about 0.8 s).
- Build: Go toolchain go1.26.9 and `golang.org/x/net` v0.60.0 (govulncheck GO-2026-6610 to
  GO-2026-6617, `net/http`).
- Session revocation (`token_version`, logout-all), bounded SSE streams, opt-in OpenMetrics, a
  deeper `/ready` check.

## Breaking changes and required operator action

1. **Local agent API token.** Every process serving the agent local listener writes
   a per-boot token (`/run/wafio/host-agent.token`, or `/run/wafio/agent.token` for a WAF-only agent;
   `--local-api-token-file` / `WAFIO_LOCAL_API_TOKEN_FILE`) and requires Bearer auth on every route
   except `/healthz`. Hand-maintained host agent units need `RuntimeDirectory=wafio` and
   `SupplementaryGroups=wafio`; `WAFIO_LOCAL_API_TOKEN_GROUP` makes the file group-readable (0640).
   On a WAF-only agent, `nginx auth_request` and SDK callers of `/v1/analyze` and `/v1/analyze-nginx`
   either keep using a loopback `--listen` or the 0660 `--socket`, or set `--analyze-token-file` /
   `WAFIO_ANALYZE_TOKEN_FILE` (at least 32 characters) and send `X-Wafio-Token`
   (nginx `proxy_set_header X-Wafio-Token`) or Bearer. A non-loopback `--listen` without that
   token file fails at start. `/internal/config` and `/internal/telemetry` always need the local token.
2. **Trusted proxies.** `proxy_config.trust_forwarded` defaults to false. Migration 000091
   keeps existing apps on true. For new apps behind a load balancer, set `trusted_proxies`
   (IPs/CIDRs, at most 64, minimum `/8` IPv4 and `/16` IPv6; empty means loopback and RFC 1918/4193
   peers). `X-Forwarded-For` is read from the right past trusted hops. Residual risk behind Docker or
   Kubernetes NAT with an empty list: a client can name any public IP.
3. **SSE authentication.** `?token=` on SSE endpoints is refused unless the control plane runs with
   `WAFIO_SSE_QUERY_TOKEN=allow`. The dashboard uses a single-use stream ticket
   (`POST /api/projects/:id/stream-ticket`).
4. **SSE stream caps.** Per user 8 streams per project and 32 in all, on top of the existing
   per-project (64) and process-wide (512) caps; over any cap the endpoint answers 429 `STREAM_LIMIT`.
5. **Boot validation.** The control plane and the portal API refuse a weak or placeholder
   `jwt.secret` / `PORTAL_JWT_SECRET` and any secret in the `internal/knownsecrets` denylist of
   values published in repository history. Rotate any secret copied from an older example config.
6. **`log.level`.** Values are `debug|info|warn|error` (default `info`, env `WAFIO_LOG_LEVEL`); an
   unknown value halts boot. It sets the `log/slog` level only.
7. **`database.password` is stored raw.** `DSN()` escapes it once; a percent-encoded value
   (`p%40ss`) is escaped twice and login fails. `WAFIO_*` variables now also work without a config file.
   `database.statement_timeout_ms` (default 15000, 0 = off, else 1000 to 600000) applies to every
   pooled connection.
8. **Host agent capability.** The host agent unit needs `CAP_SYS_PTRACE` to read
   `/proc/<pid>/exe` of protected daemons. Without it only pid 1 and the agent are protected. Check
   `journalctl -u wafio-host-agent | grep 'protected-process self-check'` for `protected_tgids` above 0
   and no `proc_access=denied`.
9. **Minimum kernel for host agent eBPF is 5.10 (owner decision 2026-10-10).** This covers the
   firewall (XDP/TC) and runtime tracing. Kernels 5.8 and 5.9 are not supported: they reject the XDP
   object (`wafio_xdp_firewall`: BPF-to-BPF call plus tail call). Earlier docs that said 5.8+ are
   superseded. Verified on 5.10, 5.15, 6.1, 6.8 and 6.12. Objects must be built with `-mcpu=v1` (`build_ebpf_multi.sh` does
   this); the bare atomic add avoids the 5.12-only atomics.
10. **Removed config keys.** `semantic_policies.<engine>.method_threshold`, `route_threshold` and
    `method_risk` never applied (no request path passed a method or route to the engines) and were
    removed on 2026-09-27; old `rules_json` that still carries them is accepted and ignored.
11. **Multi-host writes need a target (firewall IP lists v2, API breaking change).** In a project with
    more than one host, firewall list and port-policy writes need `agent_id` or `host_id`; without
    it the API answers 400 `HOST_TARGET_REQUIRED`. API clients and scripts that relied on an
    implicit host must send one.
12. **Geo allow mode and firewall features need matching agents.** The control plane switches a host
    to geo allow mode, or saves port-scoped allowlist entries, only if the agent reports the
    feature in `host_info.firewall_features` (`geo_allow`, `allowlist_ports`). Saves for other hosts
    answer 409 (`ALLOWLIST_PORTS_UNSUPPORTED`). Upgrade the host agent and its eBPF objects together
    first (see "Upgrade order").
13. **Other behaviour changes to check before upgrading.**
    - `rules_json` without a category block no longer disables engines: missing categories, fields and
      thresholds come from `engine.DefaultRulesJSON()`; an engine turns off only via `disabled: true`
      or `base_score: 0`. Config saves without `rules_json` return 400 `RULES_JSON_REQUIRED`. Operators
      who edited `rules_json` directly should review it first.
    - Invalid percent-encoded paths (`%zz`) are rejected with 400 by default
      (`proxy.reject_invalid_path_encoding`, default true); FastCGI paths are normalized.
    - 2FA setup is POST only (GET returns 405); enable requires `{code, password}`.
    - Script rules that used removed builtins stop working; dropped rules are reported as a heartbeat
      counter. A script runtime error or sandbox limit is LOG, not clean.
    - Log and challenge GUI rules record and continue the pipeline; only `allow` and `block` end
      inspection.
    - Port-scan threshold is clamped to 1 to 32 (migration 000100): stored values above 32 become 32,
      and the port-scan check stays log-only.
    - Creating an app whose listen host:port collides with another app in the project returns
      `LISTEN_HOST_TAKEN`. Migration 000094 adds the unique index.
    - Kill policies with no narrowing match need `kill_acknowledged`; agents apply an unacknowledged
      broad kill from a bundle as `alert` (upgrade the control plane and run migration 000085 first).
      New trace policies default to `match_comm_mode: word`; existing rows keep `substring`.

## Upgrade order

1. Back up the database, then run the pre-upgrade check below: migration 000094 refuses to run while
   two enabled applications on the same WAF agent share a listen address, and stops `migrate up` with
   the list of conflicts.

   ```sql
   SELECT waa.agent_id, lower(coalesce(nullif(btrim(a.listen_host), ''), '0.0.0.0')) AS host,
          a.listen_port, string_agg(a.name, ', ') AS apps
     FROM waf_agent_apps waa JOIN apps a ON a.id = waa.app_id
    WHERE waa.enabled AND a.listen_port IS NOT NULL
    GROUP BY 1, 2, 3 HAVING count(*) > 1;
   ```

   Change the listen address of, or unassign, all but one application per row before upgrading.
2. Control plane: deploy the binary and run `wafio migrate up` (migrations 000085 to 000100;
   000088 and 000092 are permanent holes). On TimescaleDB, `migrate up` also runs the per-chunk index
   statement for 000089 after the migrations, on its own connection.
3. WAF agents. Agents older than this release skip all CRS in scope for any `tag:` tuning entry, so upgrade
   agents before relying on narrow tags.
4. Host agents together with their eBPF objects. A mismatched pair can silently disable the addressed-send
   denial and the deferred-signal fix, and objects without the new markers do not support geo allow mode or scoped
   allowlist entries. Update the unit for items 1 and 8 above first.
5. Only then use the new firewall features. Refresh the GeoIP dataset on the host before enabling geo
   allow mode, and try it in Monitor mode first. Scoped allowlist entries and geo allow mode are
   offered only for agents that report `allowlist_ports` / `geo_allow`.

Migrations in this range: 000085 trace policy kill acknowledgement; 000086 WAF observability
columns; 000087 TOTP pending secret; 000089 per-app decision index; 000090 `users.token_version`;
000091 `trust_forwarded` backfill; 000093 runtime identity hardening (`match_comm_mode`, built-in
trace rules); 000094 listen-address uniqueness; 000095 agent soft delete (`agents.deleted_at`);
000096 and 000097 `agents.waf_*` observability columns; 000098 port-policy normalization (duplicates per port/protocol/direction keep the last rule, rules with an invalid port are removed, and an unknown `action` becomes `drop`, so review host port policies after the upgrade); 000099
`agents.waf_bundle_source` and `waf_bundle_generation`; 000100 port-scan threshold clamp to 32. Portal migration 000006 adds `admin_audit`.

## Security fixes

- Script rule sandbox and concurrency limits; path dot-segment handling in custom and
  tuning rules; login protection keyed by path pattern with hardened identifier extraction.
- Client IP resolution, `trust_forwarded`, geoblock on `RemoteAddr` only.
- Token revocation: `token_version` claim, `POST /api/account/logout-all`, open SSE streams re-checked
  (at most 60 s) and closed with a `stream-closed` event; server-issued TOTP secret and atomic
  failed-attempt limiting.
- Agents are soft-deleted instead of cascading a hard delete.
- Portal: suspended admin sessions invalidated, `admin_audit`, Turnstile on the contact endpoint,
  15-minute read-only impersonation token with an RFC 8693 `act` claim.
- Host agent: kill uses `pidfd` with a start-time check; protected processes are never killed and
  are tracked in-kernel; built-in suppress rules require `exe_verified`.
- eBPF firewall lockout safety and fragment handling; egress Deny All with
  connections that predate the attach; auto-jail refuses loopback, own, control-plane
  and trusted-proxy addresses.
- Firewall IP lists v2 (F1 to F11): jail kept apart from the desired state, `EGRESS_BLOCK_TOO_BROAD`
  and lockout-guard reads of canonical prefixes; adds above 10,000 allowlist entries are refused
  before parsing (`IP_LIST_FULL`) after a quadratic-time finding in the security review.
- Known leaked secrets refused at boot; a CRS archive path traversal fixed during the advisory
  lint burn-down.

## Detection changes

- Semantic coverage: incomplete coverage (truncation, field or query cap, binary or undecodable body,
  header caps, engine panic, parse budget, engine switched off, weakened verdict) sends the request to
  CRS; the verdict detail carries `coverage:<flags>`.
- CRS body view: CRS reads at most 24 KiB and 1,024 values of what its body processor extracts,
  filled by priority; what no engine inspected and the view cut becomes LOG with coverage `crs_budget`;
  `semantic_policies.on_uninspected: log|block` sets the action (default `log`).
- CRS concurrency: at most `max(2, GOMAXPROCS)` Coraza transactions at once per process;
  callers queue, no verdict changes. Body values: field cap 4,096, engine budget 256; values under
  8 KiB scan serially.
- CRS `skip_crs` `tag:<name>` skips only rules carrying that tag; umbrella or unknown tags are rejected
  at save.
- Regex conditions use RE2 with a 256-instruction cap and a per-request work budget (`regex_budget`
  coverage). WebSocket text and printable-run scanning. Body decoding for gzip, deflate
  and brotli with a process-wide decode budget (`WAFIO_BODY_DECODE_BUDGET_BYTES`).
- Semantic false-positive fixes for binary bodies, SQL-like prose and SSRF hostnames.
- Semantic false-positive follow-up (merge `2c8b699b`): the stacked-SQL lookahead stops only at a real statement
  separator. It skips quotes, line and block comments (flat and nested), `[ ]` identifiers,
  backticks, PostgreSQL dollar quotes and Oracle q-quotes; an unclosed delimiter fails closed (the
  verdict is kept). C0 control bytes, DEL, NEL and NBSP count as blanks; MariaDB `/*M!` is read as
  code like MySQL `/*!`. Measured on blazehttp: semantic-only false positives 409 to 299, default
  pipeline 1,667 to 1,592; detection unchanged (462 / 452 / 460 of 658).
- **Behaviour change (owner decision 2026-10-10): the CJK lowering was removed.** A CJK tail no longer
  lowers a semantic verdict. Payloads that mix CJK text with SQL keywords or syntax (for example a
  CJK search that quotes SQL) can now give a LOG or, in semantic-only mode, a BLOCK that an earlier
  build did not. Remedy: a path exception or tuning for the affected path. The ASCII prose rules are
  unchanged.
- L7 rate-limit and block stores are bounded LRUs (`WAFIO_WAF_STORE_MAX_ENTRIES`).
- Trace events: additional syscalls hooked, kill candidate priority ring, LSM connect and
  addressed-send denial, `match_comm_mode`.

## Host firewall

- **Geo allow mode.** Besides the country block list, a host can run "allow only these countries":
  desired state `geo_mode` `block|allow` (absent means block) with the allowed countries under
  `geo_allowed`. XDP then drops every public source outside the allowed ranges, except the allowlist,
  replies, the control plane, request-bound DHCP and IPv6 ND, private and special sources for TCP and
  ICMP (UDP and other protocols only from the interface's own subnets), ICMP errors and echo replies,
  and non-SYN packets of verified inbound TCP flows first seen before allow mode started. Capacity is
  262,144 LPM entries per address family.
- **Lockout guard.** Allow mode needs connection tracking (`CONNTRACK_REQUIRED`), at least one country (`GEO_ALLOW_EMPTY`) and the dashboard confirmation
  (`geo_allow_acknowledged`, else `GEO_ALLOW_UNACKNOWLEDGED`). Turning geo off while in allow mode resets
  the mode to block. The control plane checks capacity and empty ranges with its own GeoIP database.
- **Degraded status.** Geo is applied last and never fails the bundle. If the object, the dataset or the
  capacity does not allow it, every other rule is applied and the host reports `geo_degraded_code` and
  `geo_degraded_state` (`kept`, `ranges_cleared` or `mixed`), shown as a banner on the Firewall page.
- **IP lists v2 (F1 to F11, plan part B).** Allow and block entries are prefixes in LPM tries and are
  never expanded; ranges become a minimal CIDR cover. Applying a change is a diff, not a clear and
  refill. The jail has its own map (`origin: jail` on the local blocklist POST, `Status.jail` and
  `jail_count`) apart from the desired state. No list map evicts: over capacity the write fails with
  `IP_LIST_FULL`. A lapsed longest prefix walks one bit shorter, at most 4 levels; deeper expiring nests
  are refused (`*_NESTING_TOO_DEEP`). An egress block that covers half or more of an address family
  without an escape hatch is refused (`EGRESS_BLOCK_TOO_BROAD`). The per-IP rate limit skips replies
  and accepted inbound TCP flows. IPv6 has the same behaviour as IPv4. Frames whose L4 header is cut
  meet the lists and geo only. The port-scan threshold is at most 32.
- **Port-scoped allowlist.** An allowlist entry may carry `ports`
  `[{proto: tcp|udp|any, from, to}]` (at most 8, normalised); empty means every port and ICMP. Scoped
  entries travel under `allowlist_scoped`, so older agents ignore them and fail closed. Agents report
  `allowlist_ports`; the control plane answers 409 `ALLOWLIST_PORTS_UNSUPPORTED` for other hosts.
  Errors: `ALLOWLIST_WILDCARD_SCOPED` (scoped /0), `INVALID_PORTS` (different ports for one prefix, or
  a bad range). An entry counts as a lockout escape only when it is permanent and has no ports, or has
  a tcp/any scope on a reported SSH port. An add that would push the list above 10,000 entries is
  refused (`IP_LIST_FULL`). In geo block mode a reply from a scoped source in a blocked country is
  dropped.

## Fixed in this release

- With CRS off (project or path `disable_rule_based`, tuning
  `skip_crs "*"` or scan mode `semantic_only`), a request whose semantic coverage was partial (for
  example a value longer than 64 KiB with the payload outside the scanned head and tail) was allowed.
  It is now LOG with `inspection_incomplete:<cause>` and `coverage:<flags>` under the default
  `semantic_policies.on_uninspected: log`, and BLOCK under `on_uninspected: block`.
- A request body the agent could not decode (`Content-Encoding` it
  does not support such as zstd, a corrupt stream, or more than 8 MiB decoded) was allowed without a
  LOG unless content scan was on; CRS only saw the compressed bytes. It now follows the same
  `on_uninspected` rule, with CRS on or off. When content scan is on, its `on_incomplete` setting still
  decides for that body.
- TC egress treated a fresh XDP entry from remote to local as an
  inbound connection, so a host-opened TCP flow that predates the attach, whose remote side sent first,
  passed egress Deny All and family-wide egress blocks as replies. An inbound entry now counts only
  after verification (the host's SYN-ACK to a SYN XDP saw, or a kernel socket for exactly that tuple
  plus a listener on the local port); only a bare RST or RST|ACK skips the check.
- Host info lost keys on the control plane (found during the test server run, `ff2dea47`): the host
  telemetry and WAF ingest paths re-encoded `host_info` through a struct without `ssh_ports` and
  `firewall_features`, and each telemetry push (every few seconds) overwrote the heartbeat's full copy.
  The lockout guard therefore assumed SSH on port 22 (`SSH_PORT_ASSUMED`) on hosts whose sshd listens
  elsewhere, and geo allow / port-scoped allowlist saves were refused most of the time. Both paths
  now store the agent's object unchanged. Present since `ssh_ports` was added.

What operators will see:

- Projects that already run with CRS off get more LOG verdicts, mostly on binary request bodies (for
  example protobuf telemetry, flags `body_binary_text` and `body_binary`) and on values past the
  parse budget. On the blazehttp benign set this is 1,277 more LOG verdicts (3.8 %); no attack verdict
  and no benign BLOCK changed in any pipeline.
- With `on_uninspected: block` and CRS off those same requests are blocked. Gaps caused by operator
  choices (an engine disabled or weakened by config or tuning) and load (decode budget, script
  `busy`/`timeout`) stay at LOG. Blocks raised only by this rule do not count toward the WAF agent's
  automatic IP jail.

## Known limitations

- Kernels 5.8 and 5.9 are not supported (minimum 5.10); accepted.
- Residual semantic false positives remain (299 on the blazehttp
  semantic-only run) and CJK text that quotes SQL syntax can be blocked in semantic-only mode.
- Analyze p99 reported by the agent is about 87 to 127 ms, above the
  5 ms target, because of CRS.
- A client behind a trusted proxy is still jailed by its
  `X-Forwarded-For` address, not the TCP peer.
- Handling of connections that predate the attach is proven at program level on 5.10, 5.15 and 6.12; the VM end-to-end
  scenario is pending.
- Portal rate-limit and lockout counters are in-process and capped at
  100,000 keys.
- Extra trace syscall hooks: kernel-side severity checks stay byte-exact; the fchownat dirfd is not
  recorded; a symlink beats lexical path cleaning.
- A sub-cgroup created less than 2 s ago, or above 4,096 directories,
  still reads as host.
- eBPF firewall lockout safety and fragment handling: verified on 5.10 and later only.
- TC egress verification residuals: egress Deny All does not constrain root or
  `CAP_NET_RAW` processes; sockets are looked up in the host network namespace only, so a
  container-published (DNAT, macvlan, ipvlan) TCP connection whose conntrack entry is rebuilt mid-flow
  with the remote speaking first (agent restart, LRU eviction) is cut under egress Deny All, while new
  connections verify on their handshake; a same-user `SO_REUSEPORT` listener satisfies the listener
  check; the fix covers TCP only, so UDP traffic whose remote sends first is
  still treated as inbound.
- Uninspected-request residuals: with `on_uninspected: block`, a client can push its own gap into the
  load-capped class (exhausting the decode budget with concurrent high-ratio gzip bodies, or a script
  `timeout` driven by request size), so block mode is best effort there; a GUI allow rule still returns
  before the coverage check (a script `waf_allow()` does not); a verdict raised by the check is not sent
  to SIEM and does not count toward the temporary block policy; an XML body sent as
  `application/octet-stream` is not recognised by the body sniffer and is not scanned, with no coverage
  flag; a `/v1/analyze` call whose `body_size` exceeds the body it sends carries no flag; when the
  decode budget is exhausted a gzip form body is scanned as raw bytes and can be blocked by mistake.
- Port-scoped allowlist: ICMP errors from a scoped source are not exempt, so path-MTU
  discovery towards it can fail under a wildcard block; a UDP-scoped entry admits spoofed datagrams to
  its port; in-scope packets skip SYN-flood, port-scan, rate-limit and payload checks, so a broad scoped
  range takes that range out of flood protection; SSH port detection counts loopback-only listeners and
  a host-level DNAT (2222 to 22) shows XDP the pre-NAT port, so the SSH-port escape check can be wrong;
  a host agent whose object lacks the marker refuses a whole state that relies on a scoped escape
  entry; verifier counts on 5.10 to 6.1 are not measured.
- Known leaked secrets: the owner must rotate keys and purge git history.
- Single control plane instance, accepted.
